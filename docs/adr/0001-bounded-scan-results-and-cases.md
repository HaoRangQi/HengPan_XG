# ADR 0001：扫描结果生命周期与案例存储

日期：2026-10-07。状态：已实施，最终验证见工作记录。

## 背景

用户批准修复八项可靠性问题，重点是长时间运行内存增长。旧任务长期保存完整 K 线，并重复序列化；旧案例采用秒级 ID 和多文件非事务写入。

## 决策

- TaskManager 唯一拥有任务元数据与生命周期；TaskExtras 仅为路由投影。
- 大结果保存在 task-cache 独立 SQLite，每次仅解码一页；终态结果为权威集合，不能把淘汰的候选合并回来。
- 四个扫描页面采用 compact 进度、分页结果和按需 K 线。历史持久存储继续由 history/store.py 拥有。
- 已保存终态任务默认缓存一小时、最多八个；活动任务及保存失败任务不得被普通回收。任务日志支持重启后恢复部分结果及重试保存。
- 历史写入按条流式处理，保留原有目录暂存与事务回滚。
- 案例转入独立 cases.db，同一事务写入元数据和内容；原 cases 文件只作初始迁移来源和备份，迁移后不再双写。
- 页面继续 KeepAlive 保留操作状态，但图表在 deactivated 时释放；轮询串行、可中止，浏览器隐藏时暂停。

## 替代方案与代价

仅缩短 TTL 无法减少单次结果序列化峰值；只提高400结果上限会增大内存；删除 KeepAlive 会丢失用户操作状态。因此保留页面状态但拆开图表与数据生命周期。磁盘缓存增加本地IO，换取有界驻留内存。

## 兼容与退出旧逻辑

旧状态接口默认仍支持完整结果，当前页面明确使用 compact；旧历史详情接口仅作旧调用方兼容，现有页面使用统一轻量接口。原文件案例读写已删除，不保留 API 失败后静态数据回退。旧 Python *_days 参数保留为内部兼容名，公开界面明确 *_bars 并记录参数语义版本。

## 风险与验证

压力测试针对 Python 缓存/传输，不等同整机 RSS 或浏览器一天运行。断电/文件损坏不会自动删除未保存缓存；恢复失败会留下日志供修复。记录在 work/2026-10-06-scan-reliability。
